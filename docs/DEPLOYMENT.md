# 从本地项目到可访问网页

本文给出部署步骤，不表示 GitHub 上传或云端部署已经完成。操作仅针对新建的 `titanic_streamlit` 项目目录。

## 1. 先在本地核对

在项目的父文件夹打开 PowerShell，进入项目后执行。若当前已在项目根目录，跳过第一行：

```powershell
Set-Location -LiteralPath '.\titanic_streamlit'
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

按终端给出的本地地址打开应用。浏览六个页面，检查筛选、预测和下载。不要仅以“首页能打开”作为验证通过。

如果已经准备好该虚拟环境，只需执行最后一条命令。无需重新训练才能查看图表。`artifacts/model.joblib` 用于交互预测；其他 `artifacts` 文件提供固定实验和评估结果。

在新的空目录下载项目，再按以上步骤启动，是检验项目是否真正摆脱原电脑环境依赖的有效方法。不要把 Notebook 中某个变量仍在内存里当作可复现的条件。

## 2. 整理要上传的项目

保留应用入口、`ui.py`、`pipeline.py`、依赖清单、配置、离线训练脚本、文档，以及应用实际读取的数据和成果文件。数据来源及原发布方声明说明见 `data/README.md`。

下面内容应保持为本地文件，不上传：

- `.venv/`、`__pycache__/`、缓存目录。
- `.local/`、调试日志、浏览器截图等本地检查产物。
- 记录本机路径的源文件完整性报告。
- `.streamlit/secrets.toml` 等凭据文件（本应用一般不需要填写凭据）。
- `notebooks/original_analysis.ipynb` 参考副本；它可能保留原电脑路径、姓名等内容，默认由 `.gitignore` 忽略。

参考 Notebook 的课程提交可单独按教师要求完成，不需要为运行网页而公开上传。正式发布前查看实际待提交清单，不要把原项目整个 OneDrive 文件夹作为仓库。

## 3. 在 GitHub 建立仓库

登录自己的 GitHub 账号，按本项目已确定的交付方式建立公开仓库，例如 `titanic-analysis-app`。名称只是建议，实际地址以创建后的仓库为准。

仓库根目录应直接包含 `app.py`、`requirements.txt` 和 `.streamlit/` 等项目内容。不要多套一层文件夹后忘记调整入口路径。

可以使用 GitHub Desktop 或 Git 提交。提交前检查暂存内容，确认只包含本项目需要的文件。首次提交可以说明“添加 Titanic 分析网页及可复现实验成果”。之后按实际改动提交，例如“完善年龄筛选空数据提示”，不补造过去的提交记录。

仓库和部署后的应用均按课程展示需要提供访问链接。

## 4. 连接 Streamlit Community Cloud

进入 [Streamlit Community Cloud](https://share.streamlit.io/)，使用能够访问目标仓库的账号登录并创建应用。

填写自己的仓库、实际分支和入口 `app.py`；在高级设置中选择 **Python 3.12**。依赖由项目 `requirements.txt` 安装，不要依靠云环境偶然预装的库。[官方部署步骤](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy)

确认后启动部署，查看构建和启动日志。只有部署成功且网页能正常访问，才把平台生成的实际网址写入 README 和实验报告。目前不要填写虚构链接，也不要将本地 `localhost` 地址当作公开网址。

Community Cloud 从仓库根目录运行程序；本地也从根目录启动，项目内保持相同目录关系。[官方文件组织说明](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/file-organization)

## 5. 云端常见问题

| 现象 | 处理方法 |
|---|---|
| 找不到模块 | 检查文件是否提交，核对 `requirements.txt` 和大小写；Linux 文件名区分大小写 |
| 找不到 CSV 或模型 | 检查仓库内文件与代码使用的相对路径，不使用开发电脑的个人绝对路径 |
| 模型提示 scikit-learn 版本不同 | 使用训练时版本，或在当前固定依赖环境重新运行训练脚本并重新导出完整成果 |
| 加载自定义处理器失败 | 确认 `pipeline.py` 在仓库中，模型中的类可以按相同模块路径导入 |
| 图表能看但预测不可用 | 检查 `model.joblib` 是否存在，模型加载日志是否有异常 |
| 操作筛选时非常慢 | 检查是否在页面内重复训练；应用应读取离线成果并缓存模型 |
| 数据筛选后为空 | 页面应给出无记录提示，不将空样本生存率当作 0% |
| 手机排版拥挤 | 检查图表自适应、列数和文字换行，保留电脑版用于正式讲解 |

完整训练与三个特征对照实验已经完成。模型如需重新生成，在本地固定环境执行 `python scripts/train.py`；添加 `--ablation` 可同时复现训练部分的三个特征对照。不要在云端每次访问时运行完整训练脚本。

## 6. 发布后验收

在未登录自己开发账号的浏览器窗口和另一台设备上检查：

1. 链接可以打开，访问范围符合课程展示要求。
2. 六个页面可以切换，图表和表格加载完整。
3. 联动筛选显示正确样本数，原始年龄缺失状态处理清楚。
4. 留出评估为 179 人，正确 149 人；没有与测试预测混淆。
5. 单人预测可运行，未知年龄能按处理器规则处理。
6. 查询乘客编号和下载 418 条预测有效。
7. 网页数字与项目成果、报告一致。

现场演示前提前打开应用并检查网络。保留本地启动方式和已有图表作为网络故障时的展示材料。

## 7. 课程交付

按教师要求分别提交数据集、代码、实验报告，并参加中期检查。GitHub 仓库与网页链接可写入报告的“项目实现与复现”部分。工作量通过清洗、分析、模型实验、工程实现和真实测试记录展示，不以网页装饰数量或提交次数替代分析质量。
